# Sidekick v0.2.6 검증 보고서

상태: 최종 소스의 수치 검사와 시각 검토 완료. 아래 결과는 배포 전 검증 결과이며, 최종 CI·배포 확인은 별도 기록합니다.

## 변경 내용

- 베레모에 실제 빈 내부 공간과 연결된 안감·입구·겉감을 구성했습니다. 각 모양의 선택된 부분이 입구 안으로 들어가며, 전체 모자를 몸체 크기로 늘리지 않습니다.
- Heart의 자연스러운 착용, Flower의 지지점에서 아래로 처지는 형태, Square의 기존 착용 방향을 기준으로 조정했습니다.
- 움직임에 따라 접촉점이 바뀌면서 모자가 갑자기 펴지거나 이동하던 원인을 수정했습니다. 정지 상태의 천 모양을 유지하는 모양별 설정을 전환 중에도 보간합니다.
- 목도리와 눈 추적 코드는 이번 베레모 수정에서 변경하지 않았습니다.
- Studio에 배경·글자·캐릭터 배치를 편집하는 장면 편집기, 드래그 배치, 장면 JSON, 독립 고해상도 PNG 출력을 추가했습니다. OG 이미지는 흰 1200×630 화면 중앙에 작게 배치했습니다.

## 검증 범위

최종 결과와 원본 측정 자료는 함께 제공하는 JSON 및 압축 JSONL에 기록합니다.

- 정지 각도: 35개 모양 × 수평각 0~345도(15도 간격, 24개) × 수직각 −90~90도(15도 간격, 13개) = 10,920개
- 활동 극값 각도: 실제 활동에서 선택한 8개 상태 × 같은 전체 각도 = 87,360개
- 시간 변화: 35개 모양 × 6개 활동/회전 경로 × 181개 프레임(30fps) × 2개 시점 = 76,020개
- 중간에 목표가 바뀌는 모양 전환: 3개 경로 × 121개 프레임(60fps) × 2개 시점 = 726개
- 합계: 175,026개 렌더링 사례. 시간 변화의 모든 프레임에 전체 312개 각도를 곱한 검사는 아닙니다.
- 별도 실제 삼각형 검사: 1,230개 상태. 정지·축별/복합 회전 455개, 실제 중단 전환 363개, 추가 전환 132개, 전체 모양과 Heart 사이의 전환 280개.

## 렌더링 검사 결과

175,026개 사례의 중복 없는 전체 범위를 확인했습니다. 뒷면 제거로 인한 모자 사라짐과 진단 깊이 충돌은 0건이었습니다. 추가 확인 대상으로 분류된 정지 100개, 활동 각도 1,371개, 시간 변화 234개는 짝지은 몸체 포함/모자 단독 이미지로 판정했습니다. 활동 각도 중 1,157개는 엄격한 윤곽 조건으로 자동 분류했고, 나머지 214개 및 정지·시간 변화 대상은 직접 시각 검토했습니다. 미해결 대상은 0개입니다. 진단 대상으로 분류된 수를 결함 수로 해석하면 안 됩니다.

## 완료된 삼각형 검사

1,230개 상태 모두 몸체와 천의 교차 및 천 자체 교차 0건이었습니다. 연결성, 면 방향, 법선, 퇴화 삼각형 검사도 통과했습니다. 최종 접촉 보정의 최대 이동은 몸체 좌표 단위로 0.0045였고, 검사 상한 0.006 이내였습니다.

검사한 코드 커밋: 2ec3c693dc6eb106273ddab9e5e214474c4fddbe. 최종 배포 커밋에는 이후 문서·검증 자료·OG 배치 및 배포 테스트 수정이 포함될 수 있습니다. 핵심 소스 SHA-256은 geometry-report.json에 기록되어 있습니다.

## 수정 전후 대표 재현

- Boom에서 Heart로 전환을 시작할 때 첫 프레임의 모자 최대 이동이 약 0.098743에서 0.001837로 줄었습니다. 해당 이미지 마스크 변화율은 21.49%에서 0.61%로 줄었습니다.
- Cookie6Sided의 특정 idle 연속 프레임에서 나타나던 큰 접촉점 이동, SoftBurst의 유사 이동, 중단 전환 시 목표 이름 변경으로 생기던 위치 변경을 회귀 검사에 포함했습니다.
- 아래에서 보이던 겉감과 띠 사이의 틈, 접힌 안감과 겉감의 실제 교차를 단순히 가리는 대신 천 단면과 연결 구조를 수정했습니다.

## 성능 비용

정확도를 위한 CPU 비용 증가가 있습니다. 한 서버에서 순차 ABBA 방식으로 세 전환 경로를 비교한 결과, 활성 전환의 중앙값은 기존 11.08~13.23ms에서 16.08~18.93ms로 약 43~45% 증가했습니다. 현재 p95는 32.8~41.1ms였습니다.

충분히 캐시가 채워진 정지·호흡 프레임의 중앙값은 약 0.071ms였습니다. 최초 피팅은 측정한 세 모양에서 약 11~66ms였으며, 모든 최초 프레임이 저렴하다는 뜻은 아닙니다. 변경 프레임의 GPU 업로드 요청량은 75,048바이트에서 49,200바이트로 34.4% 줄었고 드로우·버퍼 수는 유지했습니다. 이는 서버 CPU와 API 호출 측정이며 저사양 기기에서 60fps를 보장하지 않습니다. 원본 표본과 재현 스크립트는 performance-artifacts에 있습니다.

## 한계

- 사용자가 허용한 범위 안에서 전환 중 입구가 잠시 열리거나 자유로운 가장자리가 펴지는 모습이 남습니다. 정지 상태와 같은 밀착도를 모든 중간 프레임에 보장하지 않습니다.
- 일부 전환 후반에는 수 프레임에 걸쳐 빠르게 내려앉고 천 형태가 복구됩니다. 검토한 Heart 경로의 최대 프레임 이동은 몸체 좌표 약 0.05966, 실제 변환 후 약 0.06008이었습니다. 별도의 순간 초기화·사라짐으로 판정하지 않았지만, 움직임이 일정하거나 눈에 띄지 않는다는 뜻은 아닙니다.
- Burst에서 Heart로 바뀌는 초반에는 약 0.0030의 착용 깊이, 약 0.0042의 정점 이동 차이가 남습니다. 실제 영상에서 지지점과 형태가 유지되는 범위로 검토했으며 수학적으로 완전히 연속이라고 주장하지 않습니다.
- 유한한 각도·시간·기본 설정을 검사한 결과입니다. 모든 연속 각도와 임의의 사용자 설정에 대한 무결함 보장은 아닙니다.
- 성능은 별도 보고서의 실제 측정값을 따릅니다. 서버 CPU 측정을 저사양 기기의 GPU 성능이나 60fps 보장으로 해석하면 안 됩니다.
